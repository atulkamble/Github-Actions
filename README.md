# GitHub Actions — Short Theory, Points & Basic Codes

## 1. What is GitHub Actions?

**GitHub Actions** is GitHub's built-in **CI/CD automation platform**.

It can automate:

**Code → Build → Test → Security Scan → Docker Build → Push → Deploy**

A workflow is usually stored here:

```text
.github/
└── workflows/
    └── pipeline.yml
```

## 2. Important Terms

| Term | Meaning |
|---|---|
| **Workflow** | Complete CI/CD pipeline |
| **Event** | Trigger that starts workflow |
| **Job** | Group of steps |
| **Runner** | Machine executing the job |
| **Step** | Individual command/action |
| **Action** | Reusable automation component |
| **Secrets** | Secure credentials/tokens |
| **Artifact** | Files generated by workflow |
| **Matrix** | Run job with multiple versions/OS |
| **Environment** | Deployment target such as Dev/Prod |

## 3. Basic Workflow

```yaml
name: Basic Pipeline

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Hello
        run: echo "Hello GitHub Actions"
```

### Remember the hierarchy

```text
Workflow
   ↓
Event / Trigger
   ↓
Jobs
   ↓
Runner
   ↓
Steps
   ↓
Actions / Commands
```

## 4. Common Triggers

### Push

```yaml
on:
  push:
    branches:
      - main
```

### Pull Request

```yaml
on:
  pull_request:
    branches:
      - main
```

### Manual Trigger

```yaml
on:
  workflow_dispatch:
```

### Schedule

```yaml
on:
  schedule:
    - cron: "0 5 * * *"
```

## 5. Common Runners

```yaml
runs-on: ubuntu-latest
```

Other examples:

```yaml
runs-on: windows-latest
```

```yaml
runs-on: macos-latest
```

You can also configure a **self-hosted runner**.

## 6. Checkout Code

```yaml
- name: Checkout Code
  uses: actions/checkout@v4
```

This downloads the repository code to the runner.

## 7. Run Linux Commands

```yaml
- name: Run Commands
  run: |
    pwd
    ls -la
    echo "Building Application"
```

## 8. Environment Variables

```yaml
env:
  AWS_REGION: us-east-1
  EKS_CLUSTER: mycluster
```

Use them:

```yaml
- run: echo $AWS_REGION
```

## 9. GitHub Secrets

Create secrets from:

```text
Repository
   ↓
Settings
   ↓
Secrets and variables
   ↓
Actions
   ↓
New repository secret
```

Example:

```yaml
${{ secrets.DOCKERHUB_USERNAME }}
${{ secrets.DOCKERHUB_TOKEN }}
${{ secrets.AWS_ACCESS_KEY_ID }}
${{ secrets.AWS_SECRET_ACCESS_KEY }}
```

**Never hardcode passwords, API keys, or tokens inside YAML.**

## 10. Docker Build

```yaml
- name: Docker Build
  run: |
    docker build -t myapp:latest .
```

## 11. Docker Hub Login

```yaml
- name: Docker Login
  uses: docker/login-action@v3
  with:
    username: ${{ secrets.DOCKERHUB_USERNAME }}
    password: ${{ secrets.DOCKERHUB_TOKEN }}
```

## 12. Docker Build & Push

```yaml
- name: Build Image
  run: |
    docker build -t ${{ secrets.DOCKERHUB_USERNAME }}/myapp:${{ github.run_number }} .

- name: Push Image
  run: |
    docker push ${{ secrets.DOCKERHUB_USERNAME }}/myapp:${{ github.run_number }}
```

`github.run_number` works similarly to a build number.

## 13. Multiple Jobs

```yaml
jobs:

  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Build"

  test:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Test"
```

Jobs run **in parallel by default**.

To make one depend on another:

```yaml
test:
  needs: build
  runs-on: ubuntu-latest
```

Flow:

```text
build
  ↓
test
  ↓
deploy
```

## 14. Conditions

```yaml
if: github.ref == 'refs/heads/main'
```

Example:

```yaml
- name: Production Deployment
  if: github.ref == 'refs/heads/main'
  run: echo "Deploying Production"
```

## 15. Basic CI/CD Example

```yaml
name: CI-CD

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:

      - name: Checkout
        uses: actions/checkout@v4

      - name: Test
        run: echo "Testing Application"

      - name: Build
        run: docker build -t myapp:latest .

      - name: Deploy
        run: echo "Deploying Application"
```

## 16. Points to Remember

1. Workflow files use **YAML**.
2. Store workflows under **`.github/workflows/`**.
3. `on:` defines **when** the pipeline runs.
4. `jobs:` defines the work to perform.
5. `runs-on:` selects the runner.
6. `steps:` defines individual tasks.
7. `uses:` executes an existing GitHub Action.
8. `run:` executes shell commands.
9. Jobs are **parallel by default**.
10. Use `needs:` for job dependencies.
11. Use **Secrets** for credentials.
12. Use `${{ }}` for GitHub expressions.
13. Use `if:` for conditional execution.
14. Use `workflow_dispatch` for manual execution.
15. Use artifacts when files need to be retained or passed between jobs.

### Easy interview line

> **GitHub Actions is an event-driven CI/CD automation platform where workflows contain jobs, jobs run on runners, and jobs contain steps.**

### Easy structure to memorize

```yaml
name:

on:

env:

jobs:
  job-name:
    runs-on:

    steps:
      - name:
        uses:

      - name:
        run:
```

**Core flow:** `Event → Workflow → Job → Runner → Step → Action/Command`
